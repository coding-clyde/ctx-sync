# ctx-sync

One source of truth for AI editor context. Write rules once in `.ai/`, compile
them into the native files every assistant expects, audit how many tokens they
consume, and block credentials before they reach CI.

- Node.js 20+ and TypeScript, ESM, `strict` mode.
- **Zero runtime dependencies.** `dependencies` is empty by contract; the CLI
  uses only Node built-ins.
- Deterministic output. Same source, same bytes.
- Safe writes. Files not generated by ctx-sync are never overwritten without
  `--force`.
- CI-ready. `ctx-sync check` catches drift and leaked secrets; `--strict` also enforces token budgets.

## Why

AI assistants each invented their own context file layout. Teams copy the same
rules into four files, they drift, nobody knows which one is current, and an
API key eventually ends up in a prompt. ctx-sync treats editor context like
code:

| Source | Compiled output | Consumer |
| --- | --- | --- |
| `.ai/**/*.md` | `CLAUDE.md` | Claude Code |
| `.ai/**/*.md` | `.cursor/rules/<id>.mdc` | Cursor |
| `.ai/**/*.md` | `.github/copilot-instructions.md` | GitHub Copilot |
| `.ai/**/*.md` | `.windsurfrules` | Windsurf |

## Quick start

```bash
npm ci && npm run build        # until ctx-sync is published to npm

ctx-sync init                  # create .ai/ with ready-to-edit templates
ctx-sync sync                  # audit, then write CLAUDE.md, .cursor/rules/, ...
ctx-sync check                 # CI gate: fail on drift or exposed secrets
```

(From a source checkout, `node dist/index.js <command>` is the same thing.)

`init` creates four generic rules (`00-overview.md`, `coding-style.md`,
`testing.md`, `security.md`) that already pass `check --strict`; replace them
with your own. Or create a rule by hand in `.ai/rules/typescript.md`:

```markdown
---
id: typescript
title: TypeScript conventions
targets: [claude, cursor, copilot, windsurf]
priority: 40
globs:
  - "**/*.ts"
  - "**/*.tsx"
tags: [typescript]
---

# TypeScript conventions

- Keep `strict: true`.
- Never add a runtime dependency.
- Use `import type` for type-only imports.
```

`ctx-sync sync` writes every enabled profile. Commit the generated files so
each editor gets the context without running a build first.

## Source format

Every `.md` or `.markdown` file under `.ai/` is one rule. Hidden files,
hidden directories, and `node_modules` are ignored. A leading H1 becomes the
rule title and is removed from the body; all remaining Markdown is preserved.

Frontmatter is optional and uses a dependency-free YAML subset: scalars,
quoted strings, booleans, numbers, inline arrays, dash arrays, and `|`/`>`
block strings. Unknown keys are preserved but not emitted.

| Key | Type | Default | Purpose |
| --- | --- | --- | --- |
| `id` | string | filename slug | Stable id and Cursor filename. Normalized to lowercase kebab case. |
| `title` | string | H1 or id | Heading used in compiled output. |
| `description` | string | first paragraph or list item | Cursor rule description. Single line, max 220 chars. |
| `targets` | profile list or `all` | all | Which editors receive the rule. |
| `priority` | number | `0` | Higher priority renders first. Clamped to -1000..1000. |
| `globs` | string or string[] | `[]` | Cursor auto-attach globs. |
| `alwaysApply` | boolean | `true` when no globs | Cursor always-apply flag. |
| `enabled` | boolean | `true` | Keep the source but omit the rule when false. |
| `tags` | string or string[] | `[]` | Metadata for humans and future tooling. |
| `maxTokens` | positive integer | config default | Per-rule audit budget. |

`files`, `patterns` and `filePatterns` are accepted as aliases for `globs`;
`assistants` and `profiles` are accepted as aliases for `targets`.

Built-in profiles are `claude`, `cursor`, `copilot`, and `windsurf` (more can
be added, see [Adding an assistant](#adding-an-assistant)). A typo in
`targets` is a build error, never a silent fallback to every editor. Duplicate
ids are also build errors.

### Programmatic readers

The CLI is built on three small, read-only modules:

- `src/readers/sourceReader.ts` — validates the source directory and parses
  Markdown into deterministic `RuleBlock`s.
- `src/readers/tokenEstimator.ts` — measures characters, lines, words and
  estimated tokens per file and per block.
- `src/readers/index.ts` — `readProjectContext()` bundles the parsed source,
  token estimates, and the native context files that already exist.

```ts
import { readProjectContext } from "ctx-sync";

const context = await readProjectContext({ rootDir: process.cwd() });
console.log(context.source.blocks, context.tokens.total, context.existingOutputs);
```

`readSourceTree` and `src/auditor/tokens.ts` remain available as compatibility
entry points.

## Commands

```text
ctx-sync init  [options]     Create a starter .ai/ folder
ctx-sync sync  [options]     Audit, then generate CLAUDE.md and the other target files
ctx-sync check [options]     Read-only CI gate: files in sync and context safe
ctx-sync --help | -h         Show help (also: ctx-sync <command> --help)
ctx-sync --version | -v      Show the version
```

| Option | Commands | Meaning |
| --- | --- | --- |
| `--targets <list>` | `sync`, `check` | Comma-separated assistants (`claude`, `cursor`, `copilot`, `windsurf`). May be repeated. Default: every profile enabled in the config. |
| `--max-tokens <n>` | `sync`, `check` | Token budget, per assistant and for the whole source. Default `4000`; `0` disables it. |
| `--strict` | `sync`, `check` | Exit 1 on warnings too, not only on critical findings. |
| `--json` | all | One JSON document on stdout, no ANSI colors. |
| `--force` | `sync` | Overwrite target files that ctx-sync did not generate. |
| `--help`, `--version` | all | |

Run it from the repository root. Color is used only on a terminal and is
disabled by `NO_COLOR`.

### init

Creates `.ai/` with starter rules. It refuses to touch an `.ai/` folder that
already has content, so it is safe to run once and never destroys your rules.

### sync

1. Reads `.ai/` and **audits first**: secrets, token budget, empty and
   duplicate rules.
2. If the audit has a **critical** finding (for example an exposed key), it
   writes **nothing**, so a leaked credential is never copied into four files.
3. Otherwise it writes the target files atomically (temp file + rename),
   rewriting only those whose content changed, and prints the audit report.

Generated files carry a stable marker:

```html
<!-- ctx-sync:generated profile="claude" version="0.1.0" -->
```

An existing file without that marker is yours: `sync` stops with exit code 2
and leaves it untouched unless you pass `--force`. Cursor cleanup only deletes
`.mdc` files that carry the marker; handwritten rules in `.cursor/rules/` are
always preserved.

### check

Writes nothing. A generated file that is missing, stale, or no longer matches
any rule is **critical**, as is any exposed secret. This is what the GitHub
Action runs. Fix drift with `ctx-sync sync` and commit the result.

### Severity and exit codes

| Severity | Examples |
| --- | --- |
| `critical` | An exposed secret or API key; a generated file out of sync (`check`); an invalid rule in `.ai/`. |
| `warning` | Token budget exceeded; an empty or duplicated rule. |

| Exit code | Meaning |
| --- | --- |
| `0` | Everything is correct (warnings are tolerated unless `--strict`). |
| `1` | Critical findings, or warnings with `--strict`. |
| `2` | Usage, configuration, or file error (missing `.ai/`, unreadable file, unmanaged target, bad flag). Printed as one `error:` line, never a stack trace. |
| `3` | Unexpected internal error. Set `CTX_SYNC_DEBUG=1` for a stack trace. |

With `--json`, stdout is a single document (schema v1: `severity`, `issues`,
`assistants`, `totalTokens`, ...). `sync --json` adds a `sync` field with the
files it wrote. Exit code 2 errors go to stderr and leave stdout empty.

Inside GitHub Actions (`GITHUB_ACTIONS=true`) each issue is also emitted as an
`::error`/`::warning` annotation with file, line and column.

## Token budgets

The estimator is deterministic and dependency-free (`heuristic-v1`): roughly
four Latin characters per token, one token per CJK character, with whitespace
and punctuation included. Treat results as a planning estimate (±20%), not a
provider-exact tokenizer. Provider tokenizers change frequently; guessing a
specific BPE table would be worse.

The CLI budget is `--max-tokens` (default 4,000, `0` disables it). Exceeding
it for the whole source or for any single assistant is a `warning`, which only
fails the run with `--strict`. Per-assistant totals measure complete generated
files, including headers; Cursor sums all its generated `.mdc` files.

The finer-grained budgets below (`tokenBudget` in `ctx-sync.config.json`,
per-rule `maxTokens`) are used by the programmatic `auditProject()` API and
are not consulted by `ctx-sync sync`/`check`:

- `maxPerProfile`: 12,000 tokens per compiled target.
- `maxPerBlock`: 2,500 tokens per rule.
- Above 1x the budget: `warning`. Above 2x: `critical`. `0` disables it.

## Secret detection

The auditor scans every source file under `.ai/` plus every rendered output.
Findings contain a rule id, path, line, column, matched length, a redacted
preview (`[redacted N chars]`), and a non-reversible fingerprint. **The raw
secret is never stored in the report or printed by the CLI.**

Detectors include:

- PEM/OpenSSH/PGP private key headers
- AWS access key IDs
- GitHub, npm, Hugging Face, Slack, OpenAI, Anthropic, Google, and Stripe keys
- Slack and Discord webhook URLs
- Database/broker connection strings with inline credentials
- Bearer tokens, JWTs, and generic credential assignments
- Obvious placeholders (`YOUR_API_KEY`, `${DB_PASSWORD}`, `example`, `xxxx`)
  are ignored. Stripe test keys produce warnings; other credentials produce
  critical findings.

Suppression options, in order of preference:

```markdown
<!-- ctx-sync:allow-secret -->
The fixture below is fake and covered by the explicit marker.
```

Or in `ctx-sync.config.json`:

```json
{
  "secrets": {
    "allowlist": ["^example-fixture-[0-9]+$"],
    "disabledRules": ["jwt"]
  }
}
```

Allowlist entries are case-insensitive JavaScript regular expressions tested
against the matched value and its full source line. Keep them narrow and
document why a fixture is safe. A detected credential may already have leaked;
rotate it even after removing it.

This scanner is a focused context-file guard, not a replacement for repository-
wide secret scanning or provider-side key revocation.

## Configuration

`ctx-sync.config.json` is optional. Defaults:

```json
{
  "sourceDir": ".ai",
  "profiles": {
    "claude": { "enabled": true, "output": "CLAUDE.md" },
    "cursor": { "enabled": true, "output": ".cursor/rules" },
    "copilot": { "enabled": true, "output": ".github/copilot-instructions.md" },
    "windsurf": { "enabled": true, "output": ".windsurfrules" }
  },
  "tokenBudget": {
    "maxPerProfile": 12000,
    "maxPerBlock": 2500
  },
  "secrets": {
    "allowlist": [],
    "disabledRules": []
  }
}
```

Output paths must stay inside the repository. Cursor output is a directory
(`project.mdc` for rules that always apply, plus one `.mdc` per rule scoped by
`globs`); the other outputs are files. Two profiles cannot write to the same path.
Unknown config keys are rejected so typos cannot silently disable protection.

## Adding an assistant

Each assistant is one file in `src/adapters/` named `<name>Adapter.ts` that
default-exports an `Adapter`. The registry in `src/adapters/index.ts` scans the
directory at startup, so nothing else changes: config validation, `--targets`,
rule `targets`, `sync`, `check` and the CLI help pick the new profile up
automatically. For a single-file target:

```ts
// src/adapters/zedAdapter.ts
import { createSingleFileAdapter } from "./shared.js";

export default createSingleFileAdapter({
  id: "zed",
  label: "Zed",
  defaultOutput: ".rules",
  title: "Zed rules",
  index: false,
});
```

For anything more specific (several files, custom frontmatter) implement
`Adapter.render()` directly, as `cursorAdapter.ts` does. Invalid adapter
modules (missing default export, bad or duplicate `id`) fail at startup with an
`adapter.invalid` error.

## GitHub Action

```yaml
name: AI context

on: [pull_request]

permissions:
  contents: read

jobs:
  ctx-sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: <owner>/ctx-sync@v1
        with:
          targets: claude,cursor   # optional; default: all enabled
          max-tokens: "4000"       # optional; 0 disables
          strict: "true"           # optional; also fail on warnings
```

The action sets up Node 20 and runs `ctx-sync check` on your repository. The
check fails (and annotates the pull request) when a generated file is missing
or out of date with `.ai/`, or when a secret is exposed. With `strict: "true"`
it also fails on warnings such as an exceeded token budget.

| Input | Default | Meaning |
| --- | --- | --- |
| `targets` | all enabled | Comma-separated assistants to check. |
| `max-tokens` | `4000` | Token budget; `0` disables it. |
| `strict` | `false` | Fail on warnings too. |

On first use the action builds `dist/index.js` with `npm ci` (only the
TypeScript dev dependencies are installed; runtime has none). Pin a tag or SHA
in production. The same gate works without the action:

```bash
ctx-sync check --strict
```

## Development

```bash
npm ci
npm test          # builds, compiles tests, runs node --test
npm run build     # tsc -> dist/
npm run sync      # build + regenerate this repository's own context files
npm run check     # build + verify them (what CI runs)
```

Tests use only `node:test` and `node:assert/strict`. They create isolated
fixtures in the OS temp directory, inject clocks where needed, and never touch
the network. CI runs Node 20, 22, and 24 plus a self-test of the Action.
