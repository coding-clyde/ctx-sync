# ctx-sync

One source of truth for AI editor context. Write rules once in `.ai/`, compile
them into the native files every assistant expects, audit how many tokens they
consume, and block credentials before they reach CI.

- Node.js 20+ and TypeScript, ESM, `strict` mode.
- **Zero runtime dependencies.** `dependencies` is empty by contract; the CLI
  uses only Node built-ins.
- Deterministic output. Same source, same bytes.
- Safe writes. Files not generated by ctx-sync are never overwritten without
  `--force`.
- CI-ready. `build --check` catches drift; `audit` checks budgets and secrets.

## Why

AI assistants each invented their own context file layout. Teams copy the same
rules into four files, they drift, nobody knows which one is current, and an
API key eventually ends up in a prompt. ctx-sync treats editor context like
code:

| Source | Compiled output | Consumer |
| --- | --- | --- |
| `.ai/**/*.md` | `CLAUDE.md` | Claude Code |
| `.ai/**/*.md` | `.cursor/rules/<id>.mdc` | Cursor |
| `.ai/**/*.md` | `.github/copilot-instructions.md` | GitHub Copilot |
| `.ai/**/*.md` | `.windsurfrules` | Windsurf |

## Quick start

```bash
npm ci
npm run build

node dist/cli.js --help
node dist/cli.js build
node dist/cli.js build --check
node dist/cli.js audit
```

Create a rule in `.ai/rules/typescript.md`:

```markdown
---
id: typescript
title: TypeScript conventions
targets: [claude, cursor, copilot, windsurf]
priority: 40
globs:
  - "**/*.ts"
  - "**/*.tsx"
tags: [typescript]
---

# TypeScript conventions

- Keep `strict: true`.
- Never add a runtime dependency.
- Use `import type` for type-only imports.
```

`ctx-sync build` writes every enabled profile. Commit the generated files so
each editor gets the context without running a build first.

## Source format

Every `.md` or `.markdown` file under `.ai/` is one rule. Hidden files,
hidden directories, and `node_modules` are ignored. A leading H1 becomes the
rule title and is removed from the body; all remaining Markdown is preserved.

Frontmatter is optional and uses a dependency-free YAML subset: scalars,
quoted strings, booleans, numbers, inline arrays, dash arrays, and `|`/`>`
block strings. Unknown keys are preserved but not emitted.

| Key | Type | Default | Purpose |
| --- | --- | --- | --- |
| `id` | string | filename slug | Stable id and Cursor filename. Normalized to lowercase kebab case. |
| `title` | string | H1 or id | Heading used in compiled output. |
| `description` | string | first paragraph or list item | Cursor rule description. Single line, max 220 chars. |
| `targets` | profile list or `all` | all | Which editors receive the rule. |
| `priority` | number | `0` | Higher priority renders first. Clamped to -1000..1000. |
| `globs` | string or string[] | `[]` | Cursor auto-attach globs. |
| `alwaysApply` | boolean | `true` when no globs | Cursor always-apply flag. |
| `enabled` | boolean | `true` | Keep the source but omit the rule when false. |
| `tags` | string or string[] | `[]` | Metadata for humans and future tooling. |
| `maxTokens` | positive integer | config default | Per-rule audit budget. |

Valid profiles are `claude`, `cursor`, `copilot`, and `windsurf`. A typo in
`targets` is a build error, never a silent fallback to every editor. Duplicate
ids are also build errors.

## Commands

```text
ctx-sync build [options]     Compile .ai/ to native editor files
ctx-sync audit [options]     Audit tokens and secrets without writing
ctx-sync --help
ctx-sync --version
```

### build

| Option | Meaning |
| --- | --- |
| `--root <dir>` | Repository root. Default: current directory. |
| `--source <dir>` | Source directory. Default: config or `.ai`. |
| `--profile <name>` | Build only this profile. Repeatable. |
| `--check` | Write nothing; exit 1 when outputs are stale. |
| `--dry-run` | Write nothing; print the plan. |
| `--force` | Allow overwriting files without a ctx-sync marker. |
| `--json` | Machine-readable summary on stdout. |
| `--github` | GitHub Actions annotations on stdout. |
| `--quiet` | Hide the per-file report. |
| `--no-color` | Disable ANSI color. |

`--json` and `--github` are mutually exclusive because both own stdout.

Builds abort before writing if any source rule has an error. Writes are atomic
(temp file + rename). Files are only rewritten when content changes. Generated
files contain a stable marker:

```html
<!-- ctx-sync:generated profile="claude" version="0.1.0" -->
```

Existing files without that marker are reported as `build.unmanaged-file` and
left untouched. Cursor cleanup only deletes `.mdc` files that carry the marker;
handwritten rules in `.cursor/rules/` are always preserved.

### audit

`audit` renders the current source in memory, measures the exact content that
`build` would write, scans source and rendered output for secrets, and writes
nothing.

| Option | Meaning |
| --- | --- |
| `--root`, `--source`, `--profile` | Same as build. |
| `--max-profile-tokens <n>` | Override `tokenBudget.maxPerProfile`; 0 disables. |
| `--max-block-tokens <n>` | Override `tokenBudget.maxPerBlock`; 0 disables. |
| `--fail-on <level>` | `warning` (default), `critical`, or `never`. |
| `--json` | Full schema-v1 report on stdout. |
| `--github` | Annotations with file/line/column. |
| `--quiet` | Hide token tables; findings and secrets remain. |

Exit codes:

| Code | Meaning |
| --- | --- |
| `0` | Clean, or findings below the selected threshold. |
| `1` | Audit findings meet `--fail-on`, or `build --check` found drift. |
| `2` | Invalid CLI usage, config, or source. Nothing was written. |
| `3` | Unexpected internal failure. |

## Token budgets

The estimator is deterministic and dependency-free (`heuristic-v1`): roughly
four Latin characters per token, one token per CJK character, with whitespace
and punctuation included. Treat results as a planning estimate (±20%), not a
provider-exact tokenizer. Provider tokenizers change frequently; guessing a
specific BPE table would be worse.

Defaults:

- `maxPerProfile`: 12,000 tokens per compiled target.
- `maxPerBlock`: 2,500 tokens per rule.
- Above 1x the budget: `warning`.
- Above 2x the budget: `critical`.
- A budget of `0` disables that check.

Per-rule `maxTokens` overrides `maxPerBlock`. Profile totals measure complete
generated files, including headers. Cursor totals sum all generated `.mdc`
files for the profile.

## Secret detection

The auditor scans every source file under `.ai/` plus every rendered output.
Findings contain a rule id, path, line, column, matched length, a redacted
preview (`[redacted N chars]`), and a non-reversible fingerprint. **The raw
secret is never stored in the report or printed by the CLI.**

Detectors include:

- PEM/OpenSSH/PGP private key headers
- AWS access key IDs
- GitHub, npm, Hugging Face, Slack, OpenAI, Anthropic, Google, and Stripe keys
- Slack and Discord webhook URLs
- Database/broker connection strings with inline credentials
- Bearer tokens, JWTs, and generic credential assignments
- Obvious placeholders (`YOUR_API_KEY`, `${DB_PASSWORD}`, `example`, `xxxx`)
  are ignored. Stripe test keys produce warnings; other credentials produce
  critical findings.

Suppression options, in order of preference:

```markdown
<!-- ctx-sync:allow-secret -->
The fixture below is fake and covered by the explicit marker.
```

Or in `ctx-sync.config.json`:

```json
{
  "secrets": {
    "allowlist": ["^example-fixture-[0-9]+$"],
    "disabledRules": ["jwt"]
  }
}
```

Allowlist entries are case-insensitive JavaScript regular expressions tested
against the matched value and its full source line. Keep them narrow and
document why a fixture is safe. A detected credential may already have leaked;
rotate it even after removing it.

This scanner is a focused context-file guard, not a replacement for repository-
wide secret scanning or provider-side key revocation.

## Configuration

`ctx-sync.config.json` is optional. Defaults:

```json
{
  "sourceDir": ".ai",
  "profiles": {
    "claude": { "enabled": true, "output": "CLAUDE.md" },
    "cursor": { "enabled": true, "output": ".cursor/rules" },
    "copilot": { "enabled": true, "output": ".github/copilot-instructions.md" },
    "windsurf": { "enabled": true, "output": ".windsurfrules" }
  },
  "tokenBudget": {
    "maxPerProfile": 12000,
    "maxPerBlock": 2500
  },
  "secrets": {
    "allowlist": [],
    "disabledRules": []
  }
}
```

Output paths must stay inside the repository. Cursor output is a directory;
the other outputs are files. Two profiles cannot write to the same path.
Unknown config keys are rejected so typos cannot silently disable protection.

## GitHub Action

```yaml
name: AI context

on: [pull_request]

permissions:
  contents: read

jobs:
  ctx-sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Verify generated context is current
        uses: <owner>/ctx-sync@v1
        with:
          command: build
          check: "true"

      - name: Audit tokens and secrets
        uses: <owner>/ctx-sync@v1
        with:
          command: audit
          fail-on: warning
```

The composite action builds `dist/cli.js` with `npm ci` on first use if it is
absent. Runtime execution still has zero dependencies; only the build step
uses the TypeScript dev dependencies. Pin a tag or SHA in production.

Inputs: `command`, `root`, `source-dir`, `profiles` (comma-separated),
`fail-on`, `check`, and `annotations`.

The same gates work without the Action:

```bash
node dist/cli.js build --check
node dist/cli.js audit --fail-on warning
```

## Development

```bash
npm ci
npm test          # builds, compiles tests, runs node --test
npm run build     # tsc -> dist/
npm run check     # build + verify self-hosted generated files
npm run audit     # token and secret audit of this repository
```

Tests use only `node:test` and `node:assert/strict`. They create isolated
fixtures in the OS temp directory, inject clocks where needed, and never touch
the network. CI runs Node 20, 22, and 24 plus a self-test of the Action.
